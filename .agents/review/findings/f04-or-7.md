# f04-or-7: The completion-time artifact has no lifecycle or capacity bound

**Severity**: HIGH — every completed query writes a full-result file that is never deleted, retaining AD data indefinitely and eventually exhausting the output volume.
**Status**: Verified
**Branch**: — (docs-only plan amendment; no code branch)
**Commit**: `0c9e4be`

## Evidence

- `.agents/decisions.md` F04-D5 Consequence — "Artifact retention and cleanup on `E:\WWWOutput` are not addressed here and remain an open implementation-time question."
- `.agents/plans/F04-genuine-conversational-answers.md` Slice 7 — the artifact is created atomically for **every** completed job before it is marked `Completed`, and becomes the authoritative result of record for preview, headline, download, and cross-turn reuse.
- `csharp/Services/QueryJobExecutorHostedService.cs:96-97` — the only retention sweep: `jobManager.CleanupCompletedJobs(_jobRetention)`.
- `csharp/Services/QueryJobManager.cs:454-466` — `CleanupCompletedJobs` calls `_store.RemoveJob(job.JobId)` and logs. It removes **in-memory job metadata only**; there is no filesystem call in the method.
- F04-D5 also drops the 2h `IMemoryCache` entry that today bounds result residency, so the artifact becomes the sole store with no expiry replacing the one being removed.

## Predicted observable failure

Every completed query leaves a full-result file on `E:\WWWOutput` permanently. A 40k-row result is the size D5 exists to move off the heap; the extensionAttribute1 job's CSV is 263,468 bytes on disk today. After job metadata expires, the file is *orphaned* — no `QueryJob` references it, so nothing can ever attribute or reclaim it. Two consequences: sensitive AD data accumulates without a retention story, and the volume fills until the atomic temp-then-move write fails, at which point new queries cannot complete at all. A process crash between temp write and move leaves additional orphans that no sweep collects.

## What

D5 moved results from a store with automatic expiry (a 2-hour `IMemoryCache` entry) to a store with none, and explicitly deferred the lifecycle question. That deferral is not safe to carry into implementation: the cache's expiry was doing real work, and nothing in Slice 7 replaces it. The decision's own framing — "the authoritative result of record" — is what makes the gap load-bearing rather than cosmetic.

## Approach

Amend Slice 7 to own artifact lifecycle as part of the slice, not as a follow-up. Four elements: (1) delete the artifact when its job expires, by extending `CleanupCompletedJobs` to remove the file before `RemoveJob` drops the metadata that identifies it — order matters, since removing metadata first orphans the file; (2) sweep crash orphans at startup (temp files and artifacts with no live job); (3) enforce a disk-space admission check before accepting a query, so exhaustion surfaces as a clear refusal rather than a failed atomic write mid-job; (4) define ownership for artifacts reused across turns (F04-OR-2's whole-plan reuse), so a reused artifact is not deleted while a later job still points at it. Update F04-D5's Consequence so retention is no longer recorded as an open question.

## Guard proof

Docs-only amendment to an unimplemented plan; no code guard applies. Guards are specified in the amended slice: a job whose retention has expired leaves **no** artifact on disk (proven to fail against a `CleanupCompletedJobs` that removes only metadata); an artifact still referenced by a live reusing job survives its originating job's expiry (proven to fail if deletion ignores reuse ownership); and a startup sweep removes a planted orphan (proven to fail without the sweep).

## Coder dispute (if any)

None. The finding is correct. The coder recorded the gap in D5's Consequence but treated it as deferrable; the reviewer is right that it is not, because D5 simultaneously removes the expiry that currently bounds residency.

## Known gaps

The retention period for artifacts (whether it equals `_jobRetention` or is independently configurable) is left to implementation. Whether artifacts should be retained deliberately for audit is a separate question this finding does not settle — it requires only that *some* bounded lifecycle exist.
