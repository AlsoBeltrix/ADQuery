## Predicted observable failure

A cold implementation session reads `.agents/decisions.md` — the repo's canonical settled-decision record — and concludes the F04 guards exist and verification passed, so it skips writing them; the slices then land unguarded, defeating the repo's own red→green requirement. Separately, an implementer reading plan `:74` builds Slice 7's artifact migration against an artifact that is never created at completion, reproducing exactly the defect f04-or-1 was opened to fix. The two plan lines (`:74` and `:108`) directly contradict each other, so the reader's conclusion depends on which they happen to read first.

## What

Two distinct defects with one root cause — decision records were written by filling a template whose Constraints/Consequence fields presuppose implementation, at a moment when only the *ruling* had happened:

1. **Tense.** The F04 decisions record intended guards as completed ones. Contrast REQBODY-D1 (`:102`) and CSV-KILL-D1 (`:112`), where the identical wording is accurate because that work did land.
2. **Regression.** Plan `:74`'s "already happens" parenthetical is the precise claim f04-or-1 identified as false. It survived the round-1 amendment because that fix targeted the current-state evidence bullet (`:108`) and the D5 record, not the architecture narrative.

## Approach

Rewrite the five F04 decisions' Constraints lines in the future tense ("Lands with …", "must pass `scripts/verify.ps1`") so a cold reader cannot mistake a ruling for an implementation, and mark their Consequence lines as pending implementation. Leave genuinely-landed decisions (REQBODY-D1, CSV-KILL-D1, MODEL-D1, F03-D1) untouched. Delete the "already happens" parenthetical at plan `:74` and point it at the Slice 7 work that will create the artifact. Adopt the rule going forward: verification is recorded only with the implementation commit that produced it.
