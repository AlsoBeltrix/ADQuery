# f05s1-cr-1: The pure-count prompt lands on an export policy that suppresses the download

**Severity**: MEDIUM — a user asking "how many enabled users are there?" gets the scalar count
the prompt now asks for, and no way to reach the records behind it.
**Status**: Fixed — by `4f5c3a2` (F05 Slice 2), which landed before this verdict was read.
**Branch**: — (repo policy: commit on `master`, one finding per commit)
**Commit**: `4f5c3a2020d34cd532fe3e1ac73b714ad7c7a864`

## Evidence
Recorded as the reviewer stated it:

> `csharp/Configuration/prompt_template.txt:31` and `csharp/Services/ClaudeService.cs:490` now
> instruct Translate to emit a count aggregation with an empty `group_by` for bare "how many"
> questions. That shape is still treated as non-exportable:
> `csharp/Services/ExportAffordance.cs:46` returns false for `HeadlineKind.Count` whenever
> `plan.Projection.Aggregation` is non-null,
> `tests/AdQueryOrchestrator.Tests/Unit/ExportAffordanceTests.cs:77-81` asserts the same for
> 27000 rows, and `csharp/Controllers/QueryController.cs:1080` emits `downloadUrl = null` when
> `exportable` is false.

Every cited line said what the reviewer reported, against the pinned Slice 1 snapshot.

## Predicted observable failure
> A user asking "how many enabled users are there?" will now get the desired scalar count if
> the model follows the new prompt, but the completed status payload will have
> `exportable=false` and `downloadUrl=null`; a direct download request will be rejected with
> 400 "This answer has no exportable result set" even though the underlying result contains
> many matching records.

## Disposition
**Admitted at intake, and already closed at the time of intake.** The reviewer's remedy —

> make the `Count` arm export when `totalRows > 1` even for a pure-count aggregation, while
> preserving no-export behavior for zero and single-record results, and replace the existing
> pure-count no-export guard with those cases

— is precisely what F05 Slice 2 (`4f5c3a2`) implements, line for line: the `Count` arm now
reads `totalRows > 1`, `PureCountAnswer_DoesNotExport` was replaced by
`PureCountOverManyRecords_Exports` plus an overshoot guard
`PureCountOverASingleRecord_DoesNotExport`, and the two endpoint-level assertions in
`ExportPolicyIsServerEnforcedTests` moved with the same reasoning.

No new work. The finding is recorded because it is a genuine defect that genuinely existed at
the reviewed SHA, not because anything remains to do.
