# f04-or-2: Membership-step-equality artifact reuse returns a wrongly-shaped artifact

**Severity**: HIGH — reusing a *projected* artifact on membership equality alone serves the previous turn's columns and filters as if they were this turn's answer.
**Status**: Verified
**Branch**: — (docs-only plan amendment; no code branch)
**Commit**: `d7a0f27`

## Evidence

- `.agents/plans/F04-genuine-conversational-answers.md:208` — the reuse key compares **membership steps only**; `:211` explicitly expects reuse when "projection differs".
- `csharp/Services/DirectoryPlanExecutor.cs:219` — `result.Data = Project(plan.Projection)` — the stored `PlanExecutionResult.Data` is already the *projected* rows, not the raw record set.
- `csharp/Services/DirectoryPlanExecutor.cs:572-604` — `Project` applies the projection's filters (`:574-578`, skipping non-matching records entirely) and emits only `projection.Columns` (`:582-602`). Columns absent from the prior turn's projection are simply not in the artifact.
- `csharp/Services/DirectoryPlanExecutor.cs:231` — aggregation is computed from the already-projected data; `:234-238` then applies `ResultLimit` truncation.

## Predicted observable failure

Thread: "everyone under Sanjay" (projection: Name/Department) → "only those with titles" (projection adds Title, plus a `title` filter). Membership steps are byte-identical, so reuse fires. The reused artifact has no `Title` column and contains rows the new filter should have excluded. The answer, the table, and the export all come back with a missing column and an unfiltered row set, and no traversal runs to correct it.

## What

The plan treats the persisted artifact as if it were the membership set. It is not — it is the fully reduced output of one specific projection. Keying reuse on membership steps while the artifact carries projection-specific shape is a category error, and the "add the users in China" / "only with titles" refinements the plan is *built around* are exactly the turns that trigger it.

## Approach

Amend Slice 7. Reuse a *final* artifact only when the **complete serialized plan** is identical (projection, filters, aggregation, and limit included) — that is the only case where the artifact is genuinely the same answer. Membership-level reuse, if it is worth having at all, requires persisting a distinct membership-identity representation (the resolved record identities, not projected rows) and re-applying projection/filters/aggregation/limit deterministically on every turn. State that explicitly so no implementer reads "reuse the artifact" as the cheap path.
