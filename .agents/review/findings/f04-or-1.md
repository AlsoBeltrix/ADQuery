# f04-or-1: Slice 7 drops the RAM cache before every result reader is migrated

**Severity**: HIGH — the plan's D5/Slice 7 removes the only store two live readers depend on, so a completed job's preview 404s and single-record headlines silently downgrade to `count`.
**Status**: Verified
**Branch**: — (docs-only plan amendment; no code branch)
**Commit**: `b5a4d15`

## Evidence

- `.agents/plans/F04-genuine-conversational-answers.md:207` — Slice 7 migrates only **export and cross-turn reuse** to the disk artifact, then drops the 2h full-result `IMemoryCache` entry.
- `csharp/Controllers/QueryController.cs:984-989` — `GetJobPreview` returns `NotFound("Results expired or not available")` when the cache entry is absent. It is not in Slice 7's migration list.
- `csharp/Controllers/QueryController.cs:1275-1282` — `BuildHeadline` reads `result.Data[0]` from the cache to produce the `record` headline kind; with no cache the `firstRow` is null and `HeadlineClassifier.Classify` falls through to `HeadlineKind.Count` (`csharp/Services/HeadlineClassifier.cs:79`). Not in the migration list either.
- `csharp/Controllers/QueryController.cs:1090` — `System.IO.File.WriteAllBytes(outputPath, fileContent)` is the **only** result write to disk in the whole codebase (confirmed by scanning every `WriteAllBytes`/`WriteAllText` call site), and it executes **inside `DownloadAsync`, after** the cached result has already been read at `:1057-1062`. There is no artifact at job completion.

## Predicted observable failure

After the cache is removed or evicted: a freshly completed job's preview request returns 404; a single-record query renders "1 match" instead of the record; and the first download of any job has no artifact to fall back to, because the artifact is produced *by* that download.

## What

The plan's current-state evidence bullet (`:106`) asserts the completed result "is written to disk (`OutputFile`, …)" **and** held in cache, and Slice 7 leans on that disk artifact as the pre-existing "frozen set of record". That is factually wrong: the disk write is download-triggered, not completion-triggered. Slice 7 as written would delete the cache and leave four readers — preview, headline, download, cross-turn reuse — with no source.

## Approach

Amend the plan, not the code (no code has landed). Two edits: correct the false evidence bullet at `:106` so it states the artifact is written by `DownloadAsync` at `:1090` and does not exist at completion; and rewrite Slice 7 so it (a) persists a canonical artifact atomically **before** the job is marked complete and records its path on the job, (b) migrates **all four** readers — preview, headline construction, download, cross-turn reuse — and only then (c) drops the cache, with a guard exercising a freshly completed cold-cache job across all four.
