# f04-or-4: Case-fold applied at the wrong LINQ stage throws on duplicate keys

**Severity**: HIGH — the specified change does not fold buckets; it makes `ToDictionary` throw on the first case-variant pair.
**Status**: Verified
**Branch**: — (docs-only plan amendment; no code branch)
**Commit**: `0c9e4be`

## Evidence

- `.agents/plans/F04-genuine-conversational-answers.md:155` — Slice 1b specifies that "`:488`'s `.ToDictionary(g => g.Key, g => g.Count())` gains `StringComparer.OrdinalIgnoreCase`".
- `csharp/Services/QueryJobManager.cs:476-487` — the `GroupBy` that runs *first* keys on `string.Join("|", keys)` where each key is `value?.ToString() ?? "(empty)"` (`:483`). No comparer: grouping is ordinal and case-sensitive.
- `csharp/Services/QueryJobManager.cs:488` — `.ToDictionary(g => g.Key, g => g.Count())` consumes those already-separated groups.

## Predicted observable failure

`Contractor` (6,100), `contractor` (9), and `CONTRACTOR` (3) arrive at `:488` as **three distinct groups**. Adding an `OrdinalIgnoreCase` comparer to the dictionary makes their three keys compare equal, so `ToDictionary` throws `ArgumentException: An item with the same key has already been added`. Every grouped query over an attribute with any case variance faults — strictly worse than the case-sensitive behavior D4 set out to fix. The extensionAttribute1 job is a live example (`other`/`Other`/`OTHER`, `CONFROOM`/`confroom`).

## What

The comparer belongs on the grouping operation, not on the dictionary that materializes its output. The plan's wording came from the F04-D4 owner ask, which described the change as "one comparer argument" on line `:488` — an inaccurate simplification that survived into the slice. Folding also requires choosing a display spelling and counting spellings (D4 part 3), neither of which a dictionary comparer can do.

## Approach

Amend Slice 1b: pass `StringComparer.OrdinalIgnoreCase` to the **`GroupBy`** at `:476-487` (per-field folding, so the joined composite key folds field-by-field rather than relying on the joined string). Within each folded group, tally the ordinal spellings to produce both the deterministic display key (most frequent original casing, ties broken ordinally) and the distinct-spelling count D4 requires. The case-sensitive mode is the same call with the comparer omitted. Correct the "one comparer argument" characterization so no implementer repeats it.

## Files changed

- `.agents/plans/F04-genuine-conversational-answers.md:153-157` — Slice 1b's default-fold and multi-spelling bullets rewritten to fold at `GroupBy` and derive display key + spelling count from the folded group.
